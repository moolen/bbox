# Bbox CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Cobra-based `bbox` CLI that runs arbitrary commands inside the existing sandbox engine with convenient cwd mounting, domain-file-driven network allowlists, and functional interactive stdio.

**Architecture:** Extend the library with an interactive exec path that still uses the existing helper bridge and sandbox lifecycle. Keep `cmd/bbox` thin: parse flags, build `ProxyOptions` / `SandboxOptions`, and delegate execution to the library. Use pure helper functions for domain parsing and spec parsing so most CLI behavior is easy to test without spinning up sandboxes.

**Tech Stack:** Go, Cobra, `go test`, bubblewrap, existing helper bridge/runtime

---

### File Structure

Planned file ownership and responsibilities:

- `go.mod`
  Add Cobra dependency.
- `types.go`
  Extend run options with interactive stdio configuration.
- `sandbox.go`
  Add the public interactive exec entrypoint and keep buffered run behavior working.
- `helper_client.go`
  Support stdin forwarding plus optional streamed stdout/stderr fanout while preserving buffered results for existing callers.
- `internal/helperproto/messages.go`
  Extend exec protocol to carry stdin frames and interactive flags.
- `internal/helperruntime/runtime.go`
  Wire helper-side exec to consume stdin and stream stdout/stderr.
- `cmd/bbox/main.go`
  Cobra CLI root command, flag parsing, policy construction, sandbox execution, and exit code handling.
- `cmd/bbox/main_test.go`
  CLI-focused tests for parsing and effective options/policy construction.
- `helper_client_test.go`
  Client-side tests for interactive stream behavior where feasible.
- `sandbox_test.go`
  Tests for new public run API validation/default behavior.
